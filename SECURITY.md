# Security policy

## Supported versions

Security fixes target the latest stable release of each NewHeap package. Older
versions may receive fixes when the risk and upgrade impact justify it. Before
the first public release, reports are evaluated against the default branch.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability.

Use GitHub private vulnerability reporting from the repository Security tab.
If that channel is unavailable, email `info@newheap.com` with `[SECURITY]` in
the subject. Include the affected package and version, impact, reproduction
steps, and any suggested mitigation. Do not include real customer data or
active credentials.

We aim to acknowledge a complete report within five business days. We will
coordinate validation, remediation, release timing, and public disclosure with
the reporter. Response times may vary with severity and reproducibility.

## Safe harbor

Good-faith research that avoids privacy violations, service disruption, data
destruction, social engineering, and access beyond what is necessary to
demonstrate the issue is welcome. Give maintainers reasonable time to remediate
before public disclosure.
