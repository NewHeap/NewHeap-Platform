## Preferred approach

Start from the consumer's existing pattern and deliver the module as one complete change. Define a view model and a separate mutate model, mark the view model `Id` with `Filterable`, add NewHeap mapping profiles, and route create, update, and delete operations through the concrete service. Register a `DbSet`, relationships, repository, and service in the composition root. Keep normalization, validation, and query composition in the service; the controller only translates HTTP into a typed service contract.

A mutate model does not contain `CreationDateTime` or `LastModifiedDateTime`. Database entities and migrations remain owned by the consumer implementation. For a schema change, verify that the migration is generated in that consumer's database project.

Reference `NewHeap.Platform.Mapping`, import `NewHeap.Platform.Mapping`, and register consumer `Profile` classes through `NewHeapAspNetCommonOptionsBuilder.ConfigureAutoMapper`. The familiar profile, `CreateMap`, `ForMember`, `MapFrom`, `Ignore`, `IncludeBase`, `ConvertUsing`, `ConstructUsing`, `AfterMap`, `MaxDepth`, `IMapper`, and `AddAutoMapper` syntax is provided by NewHeap without an AutoMapper package dependency. Every map receives a default maximum depth of 64, including maps created through an independent `MapperConfiguration`; an explicit `MaxDepth` remains authoritative.

Convention mapping includes public source members declared by inherited interfaces. A map registered for a consumer interface therefore maps the complete interface contract even when identifiers or other shared members are declared on parent interfaces. Destination members inherited through a base class remain part of validation and mapping.

Use `ForMember(..., options => options.Ignore())` for destination members that must stay completely outside the type map, especially entity navigations, secrets and computed getters. An ignored member is not read from either source or destination. An explicit `MapFrom` expression follows AutoMapper 14 null-propagation behavior: a `NullReferenceException` or `ArgumentNullException` caused by an unloaded nullable navigation resolves to the member's default value, while unrelated exceptions still fail the map. `Condition` is only a write condition: source and destination member getters are evaluated and the resolved source member is mapped before the condition runs, so `Condition((...) => false)` is not equivalent to `Ignore()`.

Use `IncludeBase<TSourceBase, TDestinationBase>()` when a derived destination must reuse an already configured base map. Configure both maps explicitly. Included member rules, ignored members and mapping actions are inherited, while an explicit member rule on the derived map wins. Do not emulate base-map inheritance by starting another map against the same runtime destination from `AfterMap`; runtime destination selection can re-enter the derived map.

Use `MapFrom<TResolver>()` with `IValueResolver<TSource, TDestination, TDestinationMember>` when member resolution needs services. Register the resolver and its dependencies with the appropriate DI lifetime; the mapper resolves it through the mapper's existing service factory for each mapping operation. Standard mutable and read-only generic dictionaries are mapped entry by entry, including key and value conversion; concrete `ReadOnlyDictionary<TKey, TValue>` and `ReadOnlyCollection<T>` destinations are wrapped from mutable mapped results. Sources that expose different generic and non-generic enumeration paths are read through the generic collection or key/value interface selected by the mapping contract. This includes dictionary-shaped JSON objects whose non-generic items are property nodes and standalone `IEnumerable<KeyValuePair<TKey, TValue>>` sources. Standalone `KeyValuePair<TKey, TValue>` values map and validate their key and value independently. `ISet<T>` and `IReadOnlySet<T>` destinations materialize as `HashSet<T>` so set semantics and the requested interface remain intact. A compatible mutable existing collection is cleared and reused; an existing enumerable that cannot accept mapped items is replaced with a compatible destination. AutoMapper-compatible non-generic `IEnumerable`, `ICollection`, `IList`, and concrete mutable `IList` destinations are materialized or reused without extending support to non-generic dictionaries. A source mapped to `string` uses its AutoMapper 14-compatible `ToString()` representation; enum members with `EnumMemberAttribute.Value` use that value. Use `ConvertUsing` for custom whole-object conversions such as value objects or JSON representations, and `ConstructUsing` when the destination cannot or should not be created through a parameterless constructor. A destination constructor may deliberately return null when its destination is a nullable reference type. Use `AfterMap` or `IMappingAction<TSource, TDestination>` for deterministic enrichment that belongs to the mapping contract; keep persistence, remote calls and business workflow side effects outside mapping actions.

Call `IConfigurationProvider.AssertConfigurationIsValid()` during application startup or in a composition test after every profile is registered. Validation reports unmapped writable destination members, destinations that cannot be constructed, and member type pairs that have neither a supported conversion nor a configured type map. Mark intentionally external or action-populated members with `Ignore()` so the configuration documents that choice.

Profile composition follows AutoMapper 14 when the same source and destination type pair is registered more than once: configuration construction succeeds and runtime mapping uses the last registered map. Do not rely on registration order as application behavior. `AssertConfigurationIsValid()` reports the duplicate and all contributing profile names, so consolidate the member rules into one `CreateMap` call after identifying the collision.

Use `MapOnlyIfChanged` for mutate-to-entity maps. It compares each mapped source member with the current destination member through `Equals`: equal scalar values are not assigned, a null source clears a non-null destination, and nested objects or collections retain their normal reference-equality and mapping behavior. Mapping into an existing object reuses compatible nested destination objects and mutable collection instances; collections are cleared and repopulated before the condition is evaluated, so an unchanged navigation reference is not assigned through its setter again. Getter-only mutable collections are populated in place. A destination navigation with no matching source member is not mapped.

Whole-collection maps honor an explicitly configured `ConvertUsing` map before the conventional element-by-element collection mapper. Mapping a null source into an existing destination object returns that object; for a mutable collection it preserves, clears and returns the existing instance. Nested maps started through `ResolutionContext.Mapper` remain part of the same mapping operation and reuse its context.

## Avoid

- A documentation-only example without an executable path.
- Business logic, normalization, or transaction ownership in the controller.
- Consumer entities or consumer migrations in a reusable NewHeap library.
- Assuming a repository or mapping exists without proving its registration.
- Treating `MapOnlyIfChanged` as structural or deep equality for objects or collections.
- Replacing entity navigation objects or mutable collections after an in-place mapping has already updated them.
- Using `Condition(false)` as a substitute for `Ignore()`; conditions still evaluate source and destination getters.
- Resolving scoped services from a singleton mapper instance outside a valid service scope.
- Putting persistence, remote calls or business workflow side effects in mapping actions.
- Re-entering a derived map from `AfterMap` to copy base members; configure the base map once and use `IncludeBase`.
- Relying on duplicate-map registration order; the last map is runtime-compatible behavior, while configuration validation deliberately rejects the ambiguity.
- Adding unsupported AutoMapper APIs such as `ProjectTo`, `ReverseMap`, or `AutoMapper.Collection`; use the focused NewHeap mapping surface or an explicit application-owned alternative.

## Verification

Build the backend, call `AssertConfigurationIsValid`, run the mapping, service, and controller tests, and inspect the OpenAPI output. Verify that convention mapping discovers inherited interface members, ignored throwing getters are never evaluated, an explicit `MapFrom` over an unloaded nullable navigation resolves to a default value, a false condition still resolves and maps the source member before evaluation, `IncludeBase` inherits base member rules, ignores and actions while explicit derived rules win, duplicate maps construct successfully and use the last registered map at runtime while validation reports every contributing profile, mutable dictionaries are reused, concrete read-only collections and dictionaries contain converted results, dictionary and standalone key/value-pair members validate independently, and generic collection or key/value entries remain authoritative when a non-generic enumerator yields a different item shape. Verify dictionary-shaped JSON objects, object and enum-member values mapped to strings, generic `IEnumerable<KeyValuePair<TKey, TValue>>` sources, `ISet<T>` and `IReadOnlySet<T>` materialization, non-generic list materialization plus in-place reuse, and replacement of an existing enumerable that is not a mutable collection. Verify that DI resolvers/converters/actions use the active service scope, nested maps through `ResolutionContext.Mapper` keep that scope, `ConstructUsing` supports destinations without parameterless constructors and may return null for a nullable reference destination, explicit collection converter output takes precedence over conventional collection mapping, invalid configuration reports both unmapped and incompatible members, nested object and compatible mutable collection instances are reused without redundant navigation setters, getter-only mutable collections are populated, null handling remains stable, the 64-level default recursion guard and explicit `MaxDepth` remain authoritative, and `MapOnlyIfChanged` preserves its setter behavior. For a schema change, verify the real relational providers, not only EF Core InMemory.
