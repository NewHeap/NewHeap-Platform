# Agent Runs Adoption Plan

This document records library work that a consuming application asked for while adopting the agent runs
of `NewHeap.Platform.AI.Chat` on NuGet 19.0.0 and npm 0.18.0: an application with external identity
(OIDC, rights from a claims transformation per request), one tenant per host, no agents of its own next to
NewHeap's, and its own approval channel. It is a plan, not usage documentation.

Rules for all of it: every item is opt-in, so existing applications keep today's behavior; the library
stays generic; NewHeap stores and enforces only, and consumer data never grants rights; each item has
code and migrations for SQL Server and PostgreSQL, tests with authorization negatives, a release-notes
section, consumer guide and guidance updates, an executable sample case, and Angular parts with English
and Dutch texts.

## Verified on 19.0.0

- `NhAssistantSystemApprovers.InboxAsync` returns nothing to a caller with a tenant, and boards do the
  same, so a host whose resolver sets a tenant on every person cannot see or decide whole-application work.
- Agents have no place for an application's own fields.
- `NhAssistantProposalDecisions` and `NhAssistantApproverCheck` are internal; deciding works only through
  the endpoints in the approver's own request.
- `AgentRunEnded` carries run, agent and version, trigger id, skill and status with failure code, but not
  shadow, the kind of trigger, the skill version or the number of model calls;
  `NhAiUsageRecord.InvocationId` identifies the invocation context, not one model call.
- No guidance router links a generated `references/ai-*.md`, and no validator requires it.
- Imported MCP tools next to an MCP export on one host already work: imports never carry MCP exposure, the
  export skips them, and tests and guidance say so.

### 2. Extensible agent metadata

| # | Decision |
|---|---|
| MD1 | **Named, typed entries registered in code.** `AddAgentMetadata<T>(name, ...)` with a JSON shape, a size limit and a validator that runs on save as startup validates code; values stored per agent and name in a table of their own (migration for both providers), for agents in code (set in `ConfigureAgent`, read-only unless the entry is editable) and agents created at runtime. Nothing in NewHeap interprets them, and they never widen rights. Removed with the agent and carried by export and import (S7-2). |
| MD2 | **Lookup by a declared index.** An entry declares its searchable value (`IndexBy(...)`), stored in an indexed column on save; `ListAgentsAsync(name, value)` queries it with provider-neutral LINQ. |
| MD3 | **Saved per entry.** `PUT admin/agents/{id}/metadata/{name}`, also through `INhAssistantAgentConfiguration` and `CreateAgentAsync`, with the expected version: an entry of an agent created at runtime makes the agent's next version, an editable entry of an agent in code is an override with a version of its own. The audit names the entries, never their content. The agent editor has a slot per entry where the host renders its own editor, which saves itself; no generic form engine. |
| MD4 | Built by lane MD (2026-10-23): (a), kept by Lars (2026-10-23). **Values in code stay in code.** The table holds only the values of agents created at runtime and the overrides of agents in code; a value set in `ConfigureAgent` lives in the registration, is checked once at startup (or on first use in a host without the startup check) and is merged on every read, as groups in code are. Alternative (b): seed values in code into the table as code agents are upserted; not chosen, because a changed value in code would need an upsert with its own versioning, and data would no longer say what an administrator decided. |
| MD5 | Built by lane MD (2026-10-23): (a), kept by Lars (2026-10-23). **Strict JSON on save, lenient on read.** Values use web JSON defaults (camelCase); a save refuses a field the type does not have or a value that does not deserialize (`value: invalid`) and stores the type's own serialization, while reads (`Get<T>`) ignore fields the type no longer has, so removing a property in code does not break stored values. Alternative (b): accept and keep any JSON; not chosen, because the shape is the contract MD1 asks for. Alternative (c): a source-generated `JsonTypeInfo<T>` per entry; not chosen, because the assistant library is not trimmed and it would complicate every registration. |
| MD6 | Built by lane MD (2026-10-23): (a), kept by Lars (2026-10-23). **The size limit counts UTF-8 bytes of the stored JSON**: 4,096 by default, at most 65,536 (`NhAssistantAgentMetadataLimits`), checked before the validators, `value: too-long` when larger; the column has no length of its own. An application registers at most 50 entries; names are dash-case, at most 64 characters, outside `nh-`. Alternative (b): limit characters; not chosen, because bytes are what the row and an export carry. |
| MD7 | Built by lane MD (2026-10-23): (a), kept by Lars (2026-10-23). **Validators report codes per field**: `Validate(Action<T, NhAssistantAgentMetadataErrors>)` with `Add(code)` for the whole value and `Add(field, code)` for a camelCase path, dash-case codes only; a save answers them as field errors `value` and `value.<field>` (in a definition `metadata.<name>` and `metadata.<name>.<field>`), startup fails with the same list. Several validators all run. Alternative (b): a validator returning `TaskResult`; not chosen, because field errors are what the slot shows at its fields. |
| MD8 | Built by lane MD (2026-10-23): (a), kept by Lars (2026-10-23). **The searchable value is stored trimmed and in lowercase** (at most 256 characters, `value: too-long` otherwise; empty means not searchable), and `ListAgentsAsync` normalizes the value it is asked for the same way, so SQL Server and PostgreSQL find the same agents whatever their collation; an override that does not match hides the agent's value in code. An entry that is not registered or declares no `IndexBy` throws `ArgumentException` (programmer input). Alternative (b): exact, case-sensitive comparison; not chosen, because SQL Server's default collation would match what PostgreSQL does not. |
| MD9 | Built by lane MD (2026-10-23): (a), kept by Lars (2026-10-23). **One version to send.** `NhAssistantAgentMetadataDto.Version` is always what the next change sends as `expectedVersion`: the agent's version for an agent created at runtime (required; the change raises it, `AgentVersion` says the new one) and the override's own version for an agent in code, `null` while there is none (a new override starts at 1). A stored row keeps the agent version that wrote it, or the override's version. Alternative (b): a version per entry for agents created at runtime too; not chosen, because MD3 versions their entries with the agent. |
| MD10 | Built by lane MD (2026-10-23): (a), kept by Lars (2026-10-23). **Removal per entry.** `DELETE admin/agents/{id}/metadata/{name}?expectedVersion=` and `RemoveMetadataAsync` remove the value of an agent created at runtime as its next version, and the override of an agent in code so its value in code applies again; both answer the entry as it is now (200), so the slot shows the value in code again. Without a stored value nothing changes (no version, no audit). `PUT` always needs a value (`value: required`); in a definition's `metadata` a `null` removes. Alternative (b): `PUT` with `null` removes; not chosen, because for an agent in code it would be unclear whether it overrides with nothing or returns to code. |
| MD11 | Built by lane MD (2026-10-23): (a), kept by Lars (2026-10-23). **A definition carries metadata for agents created at runtime only.** `metadata` of `POST` and `PUT admin/agents` and `NhAssistantAgentRequest.Metadata` store their entries in the same save and version as the definition, and entries left out keep their values; the definition of an agent in code with `metadata` is refused with `metadata: not-allowed` (its editable entries change one by one), and resetting an agent in code keeps its overrides, which have versions of their own. Alternative (b): reset also removes the overrides; not chosen, because they are not part of the definition in code. |
| MD12 | Built by lane MD (2026-10-23): (a), kept by Lars (2026-10-23). **Two new codes**: `assistant-metadata-entry-not-found` (404) for a name that is not registered and `assistant-metadata-read-only` (409) for an entry of an agent in code without `Editable()`; an unknown agent keeps `assistant-agent-not-found` and a stale version `assistant-version-conflict`. `GET admin/agents/{id}/metadata` lists every registered entry with `editable`, `source` (`code`, `override`, `data`), the value in code next to an override, the size limit and the searchable value; the run catalog lists the entries (`AgentMetadata`) for a new agent. Alternative (b): 400 for an unknown entry; not chosen, because the entry is a resource of the route. |
| MD13 | Built by lane MD (2026-10-23): (a), kept by Lars (2026-10-23). **One audit kind per entry change.** `AdminAgentMetadataChanged` (71) with `AgentId`, `ObjectId` and the new identifier `MetadataEntry` (the name, added to the audit allow-list), `AgentVersion` the agent's new version or the override's version, and `ResultCode` `created`, `changed` or `removed`; one event per entry, also when a definition saves several, next to `AdminAgentCreated` and `AdminAgentUpdated`. Alternative (b): only the name in `ObjectId`; not chosen, because a sink filters metadata events without parsing other kinds' object ids. |
| MD14 | Built by lane MD (2026-10-23): (a), kept by Lars (2026-10-23). **Where the API lives.** The read API `INhAssistantAgentMetadata` (`ListEntries`, `GetAgentAsync`, `ListAgentsAsync`) is in `NewHeap.Platform.AI.Chat`, so background code reads it without ASP.NET; the writes are on `INhAssistantAgentConfiguration` (`GetMetadataAsync`, `SaveMetadataAsync`, `RemoveMetadataAsync`) as MD3 says, through one internal service the endpoints share. Values in code are set only in `ConfigureAgent`; an agent in code without it gets values only as overrides of editable entries. Registering a name twice is refused, because two registrations cannot be compared. Storage is self-contained per agent and name (name and JSON), so export and import (S7-2) carry the rows and import saves them through the same checks. |
| MD15 | Built by lane MD (2026-10-23): (a), kept by Lars (2026-10-23). **The slot is outside the definition form.** `nh-assistant-agent-metadata` renders below the agent editor's form, one card per entry, and the application's editor (`provideNhAssistantAgentMetadataEditors({ name, component, label })`, environment providers registered on the administration route) injects `NhAssistantAgentMetadataSlot` with the entry, `readOnly`, `saving`, `error`, `status`, `fieldErrors`, `save` and `remove`, which save with the entry's version; after a change of an agent created at runtime the other slots and the definition's next save continue on the new version. A new agent shows "save first"; an entry without an editor says that the application shows none. The mock API checks entries from `admin.agentMetadata` and takes values only per entry. The sample books the project planner on cost center CC-4100 (SPM-313) and loads its real administration with its routes so the editor is registered there. Alternative (b): the slot inside the form, saved with the definition; not chosen, because MD3 says the host's editor saves itself. |

### 3. A public decision service for application channels

| # | Decision |
|---|---|
| DA1 | **The application vouches for the person.** A public `INhAssistantProposalDecisionService` with `GetDecisionFactsAsync(person, approvalId)` (proposal hash, expiry, whether four-eyes applies, approvals still needed, whether this person may decide; no proposal content) and `DecideAsync(person, approvalId, expectedHash, decision, channel, idempotencyKey)`, where the person is the `ClaimsPrincipal` and actor id the application authenticated. It applies exactly the endpoint's checks (approver, four-eyes, hash and staleness, `RequireUnchangedSubject`, expiry, duplicates, cooldown, follow-up run) through one shared implementation, and records the channel in the content-free audit. The guidance says it is a server API whose caller vouches for the authentication. |
| DA2 | **Idempotent by state.** A repeat by the same person with the same decision and hash returns the earlier decision as a duplicate; anything else gets the ordinary refusal. The key is recorded only in the audit; no migration. |
| DA3 | Built by lane DA (2026-10-23): **the service decides exactly what the endpoint decides**: proposals of agent runs (deferred, and inline while their run waits) and deferred proposals a consultation left in the consulted agent's thread; a person's own inline chat proposal and an inline consultation proposal the asker decides are refused with the endpoint's codes (`assistant-approval-decision-invalid`, `assistant-consult-asker-decides`), because they resume a streamed turn in the person's conversation; kept by Lars (2026-10-23). |
| DA4 | Built by lane DA (2026-10-23): **the shared implementation is `NhAssistantProposalDecisions.DecideAsync` itself**: the endpoints call it unchanged (an overload passes the `web` origin), the service passes its own channel and key, and only the audit event gained `Channel` and `IdempotencyKey`; the checks were not moved or rewritten. | DA5 | Built by lane DA (2026-10-23): **duplicates through the service only, read from the proposal's state**: when the decision answers `assistant-approval-not-pending`, also for two deliveries at the same moment, the service returns the earlier decision if the proposal names the same decider and hash and its status still says that decision (approved, executing, executed, execution-failed or execution-unknown for an approval; rejected for a rejection), also when that decision came from the endpoint; stale, withdrawn, expired and resolved proposals keep the refusal. | DA6 | Built by lane DA (2026-10-23): **programmer input throws, channel data is a result**: an invalid channel, a blank expected hash, an undefined decision or a person without principal or actor id throw `ArgumentException` (the application chooses them in code); an idempotency key that is not usable fails with `assistant-approval-decision-invalid` (it comes from the channel's delivery). ### S10. The guidance routers link the AI references

Each router (`skills/newheap-*/SKILL.md`) links its `references/ai-*.md` with a short note on when to read
them, and `guidance:validate` fails when a generated reference is linked by no router of its module.

### S7-2. Export and import with locked parts (train 20)

A versioned JSON format for an agent with its run settings, skills, triggers, consultations and metadata;
import goes through the same validators as saving. A package may lock parts, such as a skill's
instructions; the administration shows them read-only and a save refuses to change them (`locked`) until
an administrator unlinks the part. It gets a plan of its own before it is built.
