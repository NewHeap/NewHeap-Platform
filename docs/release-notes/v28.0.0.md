# v28.0.0

## NewHeap.Platform.AI.Common: reasoning per chat profile

`NhAiModelProfileBuilder.WithReasoning(ReasoningEffort effort, ReasoningOutput? output = null)` says how hard the
model of a chat profile thinks, and `NhAiModelProfile.ReasoningEffort` and `ReasoningOutput` read it back.
`NhAiChatExecutor` applies it to every governed call of the profile, on `GetResponseAsync` and
`StartStreamingAsync`, with the profile that answers the call, so a fallback keeps its own setting. A caller's own
`ChatOptions.Reasoning` wins, and the caller's options stay as they are. A profile without it leaves the call as it
was, so nothing changes without the call. An application that wrapped its client to set `ChatOptions.Reasoning` can
drop the wrapper.

## NewHeap.Platform.AI.Chat and NewHeap.Platform.AI.Chat.AspNet: waiting for a turn, progress and timings

`INhAssistantConversationTurns.WaitAsync(person, conversationId, NhAssistantTurnWait, cancellationToken)` waits for the
turn of a person's chat, whoever started it, so a channel whose caller gave up, such as an MCP tool with a time limit,
no longer polls `GetAsync`. `NhAssistantTurnWait` names the bound, from zero to `MaxTimeout` (15 minutes), the language,
the active division and the progress to report. It returns the result of `SendAsync`, or the new status
`NhAssistantTurnStatuses.Running` without a message when the bound passes first. It applies the checks of a turn and
reads the conversation every two seconds while it waits, so access that ends also ends the wait and a turn on another
host is seen too. A turn that ended earlier or elsewhere is read from the conversation, which keeps no outcome per
turn: a cancelled turn reads as `completed` and a failed one has no code. The wait neither cancels the turn nor keeps it
alive.

`NhAssistantConversationTurnOptions.Progress` and `NhAssistantTurnWait.Progress`, an
`IProgress<NhAssistantTurnProgress>`, report what a turn does: `NhAssistantTurnProgressKinds` `started`, `text`,
`tool-started`, `tool-completed` and `ended`, with `NhAssistantTurnProgressTool` for a tool's id, name and outcome and
never its arguments or result. A handler that throws is logged once and asked no further.

`NhAssistantTurnTimings` says where the time of a turn went: `Total`, `Preparation` with its `McpTools`, `Retrieval` and
`Files`, `Model` and `ModelCalls`, `Tools` and `FirstText`. `NhAssistantConversationTurnResult.Timings` returns it for
a turn that reached its model, and the turn's log line now shows it, as numbers without content. The model time adds up
the durations of the turn's `NhAiUsageRecord`s, through an internal usage sink the assistant registers.

| Breaking change | Required action |
|---|---|
| `INhAssistantConversationTurns` has the new method `WaitAsync`. | Implement it in an application's own test double; the interface grows with the endpoints, so implement or mock it only there. |
| The log message of a turn's end now continues after `{ToolCalls} tool calls` with its timings. | Update a log query or alert that matches the whole message; `TurnId`, `AgentId`, `Status` and `ToolCalls` stay. |

## NewHeap.Platform.AI.Chat and NewHeap.Platform.AI.Chat.AspNet: MCP servers that connect together

An agent's MCP servers now connect at the same time when a turn starts, so a slow server holds up only itself, and
their tools keep one order, so the list a model reads stays the same from turn to turn. A server that could not be
reached is left out of turns for `NhAssistantMcpOptions.UnreachableRetryDelay`
(`NewHeap:AI:Assistant:Mcp:UnreachableRetryDelay`), 30 seconds by default, from zero to 5 minutes, so one turn pays
`ConnectTimeout` instead of every turn. Only `assistant-mcp-unreachable` counts: a refused credential belongs to one
person and is never remembered, and a change to the server and an administrator's test try it at once. While servers
connect together, the calls to credential providers of one scope still run one at a time, so a provider that uses a
scoped `DbContext` needs no change.

| Breaking change | Required action |
|---|---|
| A server that could not be reached stays out of turns for 30 seconds after it recovers at the latest, where the next turn tried it before. | None, or set `UnreachableRetryDelay` to zero to try it on every turn. |
