# v11.0.2

## NewHeap.Platform.AI.Chat.AspNet: agent triggers inside the application's transaction

A trigger published inside the application's transaction used to write its thread, run and input
to the assistant's tables at once, outside that transaction. After a rollback the run waited ten
minutes as an orphan, a committed change on the same subject could join that dead run and never
start, the rolled-back event reached the next run, and a retried transaction with the same dedupe
key was answered `deduplicated`. Now `PublishAsync` and `StartAsync`, called inside the transaction
of the context that holds the background operations, write nothing to the assistant's tables: each
trigger becomes a background operation of type `nh-ai-fire-trigger` in that transaction and fires
through the unchanged path once the transaction committed. A rollback leaves nothing behind, a
committed change always reaches its agent, deferred triggers of one agent and subject fire in
publishing order, and a retried operation fires once. Published after the commit, a trigger fires
at once as before. Maintenance now queues a run again whose background operation never committed,
instead of cancelling it.

| Adoption note | Required action |
|---|---|
| A trigger published inside the application's transaction returns the receipt outcome `deferred` (`NhAssistantTriggerOutcomes.Deferred`) without a run or conversation id; the run starts after the commit, one dispatch interval later. | Look the thread up after the commit instead of reading it from such a receipt. |
| Only the transaction of the context that holds the background operations is recognized; an ambient `TransactionScope` is not supported by the background operations. | Publish inside the transaction of that context. |
| No migration and no configuration. | None. |
